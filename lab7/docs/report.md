## 1. Описание предметной области и модели данных

В качестве уникальной предметной области для проекта выбрана **«Студия флористического дизайна и база заказов (FloraCraft Studio)»**. Система предназначена для автоматизации учёта складских запасов цветов и материалов, ведения клиентской базы, контроля статусов выполнения заказов и расчёта стоимости композиций.

### Сущности (базы данных) и их свойства:

1. **Flowers & Materials (Каталог цветов и материалов)** — справочник доступных позиций на складе:
   * `Название товара` (`Title`) — наименование цветка, зелени или упаковки;
   * `Категория` (`Select`) — классификация (*Срезанные цветы*, *Зелень*, *Упаковка*, *Декор*);
   * `Остаток` (`Number`) — текущее количество единиц на складе;
   * `Закупочная цена` (`Number`) — стоимость за одну единицу товара.

2. **Clients (Клиенты)** — база заказчиков студии:
   * `Имя клиента` (`Title`) — ФИО заказчика;
   * `Телефон` (`Phone`) — контактный номер;
   * `Статус` (`Select`) — сегментация клиента (*Новый*, *Постоянный*, *VIP*);
   * `Дата первого заказа` (`Date`) — дата начала сотрудничества.

3. **Orders (Заказы)** — учёт оформленных заявок на букеты и композиции:
   * `Название заказа` (`Title`) — номер и краткое описание заказа;
   * `Клиент` (`Relation` → `Clients`) — связь с карточкой заказчика (один клиент может оформить множество заказов);
   * `Статус` (`Select`) — этап выполнения (*Новый*, *В работе*, *Готов*, *Доставлен*);
   * `Дата выполнения` (`Date`) — дедлайн сдачи или доставки букета;
   * `Итоговая сумма` (`Number`) — общая стоимость заказа.

4. **Order Items (Состав заказов)** — детализация позиций внутри каждого заказа:
   * `Позиция` (`Title`) — описание конкретной составляющей букета;
   * `Заказ` (`Relation` → `Orders`) — привязка позиции к конкретному заказу;
   * `Материал` (`Relation` → `Flowers & Materials`) — привязка к номенклатуре со склада;
   * `Количество` (`Number`) — количество единиц материала в заказе;
   * `Цена за ед.` (`Number`) — стоимость единицы позиции;
   * `Стоимость позиции` (`Formula`) — автоматически вычисляемая стоимость (`prop("Количество") * prop("Цена за ед.")`).

## 2. Использование ИИ: промпты, результат и доработки

Для проектирования архитектуры баз данных и генерации тестовых наборов данных использовался ИИ-ассистент.

### Примеры использованных AI-промптов:
1. **Генерация модели данных:**  
   *«Придумай уникальную предметную область для учебного проекта в Notion: студия флористического дизайна FloraCraft. Нужно 4 связанные сущности, минимум 2 связи Relation, свойства типов Title, Select, Date, Number, Formula. Опиши модель данных и объясни, зачем нужна каждая связь».*
2. **Генерация тестовых данных:**  
   *«Сгенерируй по 10 реалистичных записей для каждой из четырёх таблиц (Каталог материалов, Клиенты, Заказы, Состав заказов) в виде структурированных таблиц для переноса в Notion».*
3. **Настройка формул и представлений:**  
   *«Напиши формулу для Notion, которая перемножает свойства "Количество" и "Цена за ед." в таблице состава заказов».*

### Что было проверено и исправлено после генерации ИИ:
* **Уточнение связей:** Изначально ИИ предложил связать `Orders` и `Flowers & Materials` напрямую. При проверке выяснилось, что при таком подходе невозможно указать разное количество цветов каждого вида в одном букете. Была введена промежуточная сущность **`Order Items`**, реализующая связь «многие-ко-многим» через два поля `Relation`.
* **Корректировка формулы:** Уточнены названия свойств в синтаксисе формулы Notion (`prop("Количество") * prop("Цена за ед.")`), чтобы исключить ошибки типов данных при расчёте.

## 3. Освоенные компоненты и настройки Notion

В рамках выполнения работы настроены и применены следующие инструменты платформы:
* **Базы данных (Databases):** созданы 4 отдельные базы данных (`Flowers & Materials`, `Clients`, `Orders`, `Order Items`), каждая наполнена 10 записями.
* **Типы свойств (Properties):** использованы `Title`, `Select`, `Phone`, `Date`, `Number`, `Relation`, `Formula`.
* **Связи между таблицами (Relations):** настроены 3 связи (`Orders ↔ Clients`, `Order Items ↔ Orders`, `Order Items ↔ Flowers & Materials`).
* **Вычисляемые поля (Formulas):** настроено свойство `Стоимость позиции` для автоматического подсчёта суммы по каждой строке заказа.
* **Представления (Views):** для базы данных `Orders` созданы два представления — табличное (`Table`) для детального редактирования и канбан-доска (`Board`), сгруппированная по полю `Статус`, для визуального контроля этапов сборки.
* **Интерактивные кнопки (Buttons):** добавлена кнопка быстрого действия для автоматизации создания новой записи заказа.
* **Публикация (Publish to web):** рабочее пространство опубликовано в веб с открытым доступом по ссылке.

## 4. Ограничения бесплатного тарифа Notion

При работе на бесплатном тарифе (Free Plan) были отмечены следующие особенности и ограничения:
* Ограниченный размер загружаемых файлов (до 5 МБ на один файл), что не позволяет загружать тяжёлые медиафайлы без сжатия.
* Ограниченная история версий страниц (доступна только за последние 7 дней).
* Ограничения на количество блоков при добавлении сторонних участников в рабочее пространство (Free Plan ориентирован преимущественно на персональное использование).
* Отсутствие расширенных настроек гранулярных прав доступа к отдельным базам данных внутри публичной страницы.
